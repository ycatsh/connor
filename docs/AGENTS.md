# AGENTS.md

This guide is for AI coding agents (Claude Code, Copilot, Codex, etc.) working in this repo.
See [docs/CONTRIBUTING.md](CONTRIBUTING.md) for the human version. See [.github/agents/rules.md](../.github/agents/rules.md) for what maintainers must set up to make the rules below actually be followed.

<br>

## Project overview

**connor** keeps an organized file system organized. It sorts new files into the folders you allow, learns from the files already there, and renames files to your per-folder naming schemes. Every run is shown as a plan first and journaled, so it can be undone.

- **License**: MIT
- **Primary language**: Python 3.11+
- **Interface**: CLI (argparse), one-key review prompt
- **Placement**: model2vec static embeddings, nearest files, name match and file type. No LLM.
- **Storage**: SQLite cache and journal in the user cache and data dirs. No external services.
- **Build/deps**: [uv](https://docs.astral.sh/uv/), hatchling

<br>

## Quick start commands

```bash
# Install dependencies (including dev tools)
uv sync

# Run the test suite
uv run pytest

# Lint (ALWAYS run before calling a change done)
uv run ruff check .

# Format
uv run ruff format .

# Type check (strict)
uv run mypy

# Run the CLI
uv run connor
```

CI (`.github/workflows/ci.yml`) runs all four checks on Linux, macOS and Windows on every PR.
Run them locally before finishing a change; don't rely on CI to catch formatting.

## Architecture & package structure

Everything lives under `src/connor/`.

- **`cli/`**: talks to the user. `main.py` parses arguments and dispatches. `commands.py` has one handler per command; it calls `core` and hands results to `views.py`. `term.py` owns color, alignment and one-key prompts. Only `views.py` and `term.py` print.
- **`config/`**: `schema.py` holds frozen dataclasses, one per config section. `loader.py` validates TOML strictly and reports every problem with a "did you mean". `formats.py` parses naming scheme formats. `paths.py` finds the config, cache and data dirs. `template.toml` is what `connor config init` writes.
- **`core/`**: does the work. One module per job:
  - `scan.py`: inbox and library walk, safety skips, `protected()` for any folder.
  - `extract.py`: title, opening text and creation date from documents.
  - `embed.py`: the `Embedder` protocol, model2vec loading, the one-time download.
  - `index.py`: SQLite cache of vectors and text, plus stored calibration.
  - `place.py`: the three placement signals, tiers, and `calibrate()`.
  - `labels.py`: placement into labels for `sort --by`.
  - `cluster.py`: grouping and naming of leftovers for new folders.
  - `names.py`: naming schemes, rendering, lint, junk names, dates in text.
  - `lint.py`: library lint and the `--fix` rename plan.
  - `plan.py`: `Decision`, `Action`, `Plan`, the editable plan text and JSON.
  - `sort.py`: the pipeline that ties scan, index, place, rules, duplicates and names together.
  - `journal.py`: apply and undo, journaled before every step.
  - `dupes.py`, `find.py`, `watch.py`: duplicates, search, and the scheduled loop and service files.
- **`globs.py`**: the folder glob matcher used by config and core.
- **`cron.py`**: the cron schedule parser used by config and watch.
- **`errors.py`**: `ConnorError` and its subclasses. Core raises them; only `cli` catches them.

Imports go one way: `cli` imports `core` and `config`. `core` imports `config` and `errors`. `core` never imports `cli`. No global state.

## Development workflow

1. Write the tests first. Run them and watch them fail. Then implement.
2. Tests must check real behavior with realistic inputs and edge cases. Never write a test shaped to pass, or one that mirrors the implementation. If a test fails, fix the code, unless the test was wrong about the spec.
3. Make focused, incremental changes. Don't refactor unrelated code in the same change.
4. Run `uv run pytest`, `uv run ruff check .`, `uv run ruff format .` and `uv run mypy` before calling the change done.

### Correctness

`core/journal.py` and `core/scan.py` decide which files move, where they go, and which folders are off limits.
Bugs there are the highest-severity class of issue in this repo. The rules:

- Never delete a file. Never overwrite a file.
- Every move is written to the journal before it happens, so a crash can be undone.
- Safety skips (hidden folders, repos, vaults, app bundles, build dirs, `.connorignore`) always win over the user's include list.

### Privacy

Nothing that could identify a real person goes into this repo: names, emails, schools, course codes, real folder or file names, timezones. Use made-up examples (`school/2026/fall/BIO101`, `work/acme/report`).
Office fixtures are generated by `tests/fixtures/make_fixtures.sh`, which pins `TZ=UTC`, uses a throwaway LibreOffice profile, and fails if the current user name, host name or home path shows up in any output.

## Code style & conventions

- **Types**: full hints everywhere, builtin generics (`list[str]`, `Path | None`). `mypy --strict` must pass.
- **Data**: frozen dataclasses (`@dataclass(frozen=True, slots=True)`) between modules. No loose tuples or dicts.
- **Paths**: `pathlib.Path` only.
- **Errors**: raise a `ConnorError` subclass with a clear one-line message. No bare `except`. No error strings returned as data.
- **Code organization**: keep each public function followed immediately by the private helpers it calls, in call order, so a file reads top to bottom like its call flow.
- **Comments**: none in code. Names and types carry the meaning. `config/template.toml` is the exception, since its comments are user docs.
- **Docstrings**: only where a public function is not obvious from its name and types. Always this Google style: imperative summary line ending in a period, then `Args`, `Returns`, `Raises`, in that order, leaving out empty sections.

  ```python
  def render_name(scheme: Scheme, fields: NameFields) -> str:
      """Render a file name from a naming scheme.

      Args:
          scheme: Compiled naming scheme.
          fields: Values for each placeholder.

      Returns:
          The file name without its extension.

      Raises:
          SchemeError: A placeholder has no value.
      """
  ```

- **Text**: ASCII only in code, strings, docs and commits. Short sentences.

## Testing patterns

- `pytest`, configured in `pyproject.toml`.
- `tests/conftest.py` has an autouse `isolated` fixture. It points `HOME`, the XDG dirs and `CONNOR_CONFIG`, `CONNOR_CACHE_DIR` and `CONNOR_DATA_DIR` at a temp dir and clears `VISUAL` and `EDITOR`. No test may touch the real home dir or open a real editor.
- Placement tests use a fake embedder (`tests/fakes.py`) so they are fast and repeatable and never download a model.
- `tests/test_real_model.py` runs against the real model when `CONNOR_TEST_MODEL_CACHE` points at a cache dir holding it. CI downloads it in a separate job.
- `tests/test_startup.py` keeps light commands from loading numpy, pdfium or the model. Import heavy modules inside the functions that need them.
- The safety-critical modules (`journal.py`, `scan.py`, `dupes.py`) were mutation tested: every deliberate break of a safety check makes a test fail. Keep it that way when you change them.
- `tests/fixtures/` holds real office files (docx, odt, doc, rtf, pdf, xlsx, ods, xls, pptx, odp, epub) made from the sources in `tests/fixtures/src/`.
- Test files mirror the modules they cover (`test_scan.py`, `test_config.py`, ...).

## Commits

- Never run `git commit` or push unless the user explicitly asks for that commit, in that message.
  Preparing a diff is not permission to commit it.
- Subject line: `type: short description` (`fix:`, `feat:`, `refactor:`, `test:`, `docs:`, `chore:`), matching [docs/CONTRIBUTING.md](CONTRIBUTING.md).
- End every AI-authored commit message with a `Co-Authored-By:` trailer naming the model.
  Prefix the subject with `[AI] `. Example:

  ```
  [AI] fix: this is an example commit message

  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  ```

  `.github/workflows/ai-commit-check.yml` enforces the prefix on every PR.
  A commit with the trailer but no `[AI]` prefix fails CI and blocks merge.

## Troubleshooting

- **A test hangs**: something opened an editor or waited for input. Make sure the test relies on the `isolated` fixture and passes answers through `sys.stdin`.
- **`ruff format --check` fails in CI but you didn't touch that file**: run `uv run ruff format .` locally and diff.
- **A fixture changed after regenerating**: dates inside the files change on every run. Only regenerate when the sources change.
